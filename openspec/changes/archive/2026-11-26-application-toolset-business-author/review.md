## What shipped
`author` of an application or toolset is a business value: stored as sent (`""` = anonymous), filled with the caller on create, kept on an update that omits it, and read from the body with the audit author as fallback. It feeds `owner` in `/openai/applications`, `/openai/toolsets` and `/v1/deployments`. Apply and file migration record the admin as audit author; publication approval sets the copy's `author` to `displayAuthor`; toolset repair passes the audit author. Docs: `applications.md`, `toolsets.md`. Deploy and status responses now include `author` for applications created after this change.

## Drift from design.md
Listing routes are `/openai/...`; `copyToolSet` needs no fallback (the copy's audit author is the source's); the audit author of applied entities is read from `GET /v1/metadata/{type}/platform/{name}`, not the folder listing, which lags Redis. `docs/open_api_core.yaml` needs no change. The legacy-source publication test was dropped: it passes without the new code. In `resource-access-control` the author rule is its own requirement ("Author of a published application or toolset"), not an addition to "Approving a publication", which stays as it was: the longer text failed `validate --specs --strict`.
