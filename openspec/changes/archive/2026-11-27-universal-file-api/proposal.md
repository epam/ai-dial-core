# Proposal

## Why

Clients use different APIs and conditional-write semantics for plain files and files inside skills or projects.
Expose existing complex file URLs through `/v1` so one file client can work with all three groups without weakening resource validation.

## What Changes

- Add file content and metadata routes at `/v1/{skills|projects}/{bucket}/{resource}/files/{filePath}` and `/v1/metadata/...`.
- Use per-file ETags, multipart PUT and file metadata responses; expose the owning resource as `X-Resource-ETag` and optional `resource: {url, etag}`.
- Extend resource copy/move to complex file URLs, including cross-group operations and atomic same-resource rename.
- Keep authorization at complex resource roots, validate every mutation, enforce existing limits and publish existing logical events.
- Preserve all existing plain-file and whole-resource APIs, including their actual status codes and ETag behavior.
- Document the new contract and measure read/write latency against the existing complex file routes.

Out of scope: new resource creation paths, per-file sharing/publications, whole-resource cross-type operations,
marker walks, URL conversion, deprecation, redirects, new range support and unrelated storage changes.

## Capabilities

### New Capabilities

- `file-content`: file content, conditional mutations and single-file copy/move across plain and complex storage.

### Modified Capabilities

- `resource-listing`: add complex file metadata and in-resource folder listings in the `/v1` file shape.
- `resource-access-control`: authorize the new routes and file operations on complex roots; scope the new permissions and cross-type exception without changing legacy operations.

The existing `resource-subscription` event requirements remain unchanged and are regression-tested.

## Impact

Motivation: [issue #2404](https://github.com/epam/ai-dial-core/issues/2404), based on `unified_api.md`.
This change covers its requirements 1–12, endpoints, metadata, copy/move and measurement. No planned feature is deferred.
The design's description of current `/v2` download ETags is corrected in `design.md`; the actual route stays unchanged.

Affected modules: `server` controllers, routing, complex resource engine and tests; `storage` metadata DTOs and narrowly scoped locked storage helpers; `openapi-generator` controller registration.
Update controller OpenAPI annotations, add `docs/universal-file-api.md`, and update the relevant README and org-unit documentation.
`docs/open_api_core.yaml` is regenerated by `replaceSpec`/CI, not hand-edited. No new setting, dependency or storage format is required.
