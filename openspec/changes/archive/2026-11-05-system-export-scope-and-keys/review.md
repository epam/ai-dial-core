# Review: system-export-scope-and-keys

## What shipped

- `POST /v1/admin/system-export` takes an optional `scope` query parameter: a comma-separated list of buckets (`public`,
  `platform`), case-insensitive, spaces ignored, repeats collapsed. No `scope` selects every bucket.
  `AdminSystemExportService.resolveBucketLocations` derives the valid names from `MergedConfigStore.ADMIN_BUCKET_LOCATIONS`
  and returns the selected locations in that list's order. An empty value, an empty element or an unknown name (`org`,
  `all`) throws `IllegalArgumentException`; `AdminSystemExportController` answers it with `context.respond(400)`, as for the `403`, before the response, the
  pipe, the task and the locks exist.
- `AdminSystemExportService.export(out, start, bucketLocations)` locks and walks only the selected buckets.
- With a KMS provider (`aws`, `azure`, `gcp`), `encryption_keys` blobs of the selected buckets are exported like any other
  blob. Without one they are still excluded. `credentials` is excluded in both cases. The service gets `kmsEnabled` from
  `AiDial` (`readKmsSettings().isEnabled()`); the per-instance `excludedGroups` replaces the static list.
- `KmsSettings.isUnencrypted()` (the factory's old early-return test) and `KmsSettings.isEnabled()` (true only for `aws`,
  `azure`, `gcp`, case-insensitive). `KeyManagementServiceFactory.create` uses `isUnencrypted()`, so an unsupported provider
  still throws at startup and never falls back to plaintext.
- Controller annotation: `scope` query parameter and `400`. `docs/open_api_core.yaml` regenerated by `replaceSpec` (the
  parameter and the `400`; the existing 200 description is kept by the merge).
- Docs: `docs/admin-system-export.md` (new "Choosing the buckets", `400` row, KMS rule, restore caveat) and the README line.
- Tests:
  - `KmsSettingsTest` (new, 12): both rules, case, an unsupported name, JSON round trip with no derived properties.
  - `KeyManagementServiceFactoryTest` (new, 2): plain service for no provider and `unencrypted`; an unsupported provider throws.
  - `AdminSystemExportServiceTest` (27, 7 new): `resolveBucketLocations` valid and invalid values, only the selected buckets
    exported and locked, a held lock of an unselected bucket does not reject the export, keys exported with KMS on, keys of
    only the selected bucket.
  - `AdminSystemExportApiTest` (10, 4 new): scope selection, case and spaces, order, `400` for each invalid form with no
    `Content-Disposition` and a free lock afterwards, `403` before `scope` is read, a held `platform/` lock with
    `scope=public`, keys with KMS on. The class runs with `toolsets.security.kms` set to `aws`.

## Drift from design.md

- `KmsSettings` has two methods, not one. Using `!isEnabled()` in the factory would have made a typo in the provider run
  unencrypted, so the factory keeps its own test as `isUnencrypted()`. design.md Decision 4 was updated.
- The HTTP test for KMS on lives in `AdminSystemExportApiTest`, not in a separate class, because the class settings apply to
  every test in it. As a result the KMS-off scenarios are covered only in `AdminSystemExportServiceTest` (see Known limits).
- Tasks 4.3 (`validate --all --strict`) and 4.4 (running the `curl` examples) were removed from tasks.md at the author's
  request.
- Spec wording changed from "provider is set and is not `unencrypted`" to "provider is `aws`, `azure` or `gcp`" in the spec,
  proposal, design and docs, after the `isEnabled()` tightening.
- `toScopeName` uses `Strings.CS.removeEnd` (commons-lang3 3.18.0); the line was changed on disk after it was first written
  with `StringUtils.removeEnd`, and it was kept.

## Not done

- The full suite runs in CI.
- `openspec validate --all --strict` fails on `resource-subscription` and `user-limits` (placeholder Purpose text). Both are
  untouched by this change; the change and the `system-export` spec validate.
- The `curl` examples in `docs/admin-system-export.md` were not run against a live Core.
- Not checked: a real KMS call. The KMS-on tests store the key blobs directly and never ask the AWS client to encrypt or
  decrypt.

## Known limits

- With KMS on, the export trusts the setting. A key written before the provider was switched on, or one not yet synced from
  the write queue, can be a plaintext key in blob storage and would be exported.
- An archive with wrapped keys restores only where the same KMS key is usable. Core replaces a key it cannot decrypt
  (`ContentEncryptionKeyManagerImpl.getOrCreateKey`), so restoring without the matching KMS key makes the restored secrets
  unreadable. Documented; the import design has to handle it.
- No HTTP test covers the KMS-off wiring (`AiDial` passing `false`). A wiring bug that passed `true` with KMS off would export
  plaintext keys and only the service-level tests exist for the flag itself.
- A repeated `scope=a&scope=b` is read as the first value (`getParam`); no spec states it.
- The manifest does not record the scope or whether keys are included. An importer decides which buckets to replace from the
  entries present; a bucket exported empty is therefore not cleared on restore.
